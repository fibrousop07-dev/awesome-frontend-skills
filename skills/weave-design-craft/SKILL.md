# Weave Design Craft

Use the user's actual brief, brand material and existing design system. Read `references/composition.md`, `references/typography.md`, `references/imagery.md`, and `references/review.md` only if the runtime has not already appended those craft sections. Read `references/interaction.md` when building forms or other stateful controls. Do not load the entire collection for a small fix.

Start with a fully populated representative screen and inspect its desktop/mobile rendering before expanding the design. User-delegated creative freedom means choose and proceed, not ask repeatedly. A user-rejected direction must be substantively revised before rollout. Keep an existing product's sound design when a focused fix is requested.

Use 21st.dev component discovery where useful; inspect relevant source/license and adapt it to the brand. Do not force a React dependency or a particular template into an unrelated stack.

Review actual screenshots and the primary interaction. Identify concrete defects across clarity, hierarchy, typography, imagery and brand. Fix material issues, then recapture the affected screens. Use at most three focused review/fix cycles per build pass; report unresolved issues honestly if the cap is reached. Do not award a visual pass based on filenames, a prose plan, self-assigned average score or a missing-image fallback. User approval is not implied by a reviewer verdict.

Todo tracking is optional and outcome-based; no extra turn per document, tool call or checklist update. Respect the user's model/provider budget and all runtime permissions. Never consume Codex/OpenAI usage as fallback when the owner reserved it for other sessions.

These Weave-specific references independently apply workflow concepts inspected in Open Design. See `PROVENANCE.md`; no upstream code or templates were copied.
